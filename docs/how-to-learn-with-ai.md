# 有 AI 时怎么学（2026 版工作方式）

> 你有 Cursor / AI 助手。计划从「上课」改成「做出机器人 + 需要时再懂原理」。

## 核心结论

**对一半：** 很多语法、样板代码、文档翻译不用硬学。  
**错一半：** 若完全不懂原理，你无法判断 AI 对不对、仿真为什么倒、角色为什么不像机器人。

目标不是「成为程序员」，而是 **能指挥 AI + 能验收结果**。

## 三层深度（按这个分配精力）

| 深度 | 含义 | 举例 |
|------|------|------|
| **会指挥** | 知道要什么，能让 AI 写/改，你能跑通 | JSON schema、parse 脚本、Git 提交 |
| **懂原理** | 能判断对错，能描述问题，能改方向 | 状态机、关节限位、为什么 idle 会抖 |
| **必须亲手** | AI 替不了，必须自己练 | Blender 造型/绑定/关键帧、表演节奏、角色性格 |

## AI 可以大幅减负的

- Python 语法背诵、Coursera 系统课（**不必按原 plan 上满**）
- 从零写 parser / exporter（AI 写初版，你改参数和测试）
- OpenUSD / Isaac 文档逐页啃（**遇到问题再问 AI**，对照官方 doc）
- Modern Robotics 整套（除非某天真机/运动学卡住）
- 记 Git 命令（会 status / add / commit 即可，其余问 AI）

## 你仍然必须会的（至少「懂原理 + 亲手做过」）

| 领域 | 为什么 |
|------|--------|
| **Blender 角色与绑骨** | 这是你的机器人长什么样、怎么动；AI 不能替你审美 |
| **表演与情绪设计** | BD-X 的灵魂；你要自己设计 idle/害羞/开心 |
| **仿真里「对不对」** | 站不站得住、抖不抖、头转会不会栽——要看、要调，不能只看 AI 说「好了」 |
| **你的命令/schema 设计** | motion / head_yaw 代表什么，必须你定；AI 只能实现 |
| **版本与环境** | Isaac 5.1 vs 6.0、Python 3.11——AI 会幻觉，你要会核对 README 里的版本 |

## 推荐工作流（每个功能）

1. **你定目标**（例：读 JSON，打印每个 channel 的时间戳）
2. **AI 写最小可运行版本**
3. **你运行、看结果、说哪里不对**
4. **只补这一刻需要的原理**（例：dict 是什么、JSON 结构）
5. **能重复**：下次同类问题少问一点
