# Project Charter

## 这个项目到底是什么

**我想做一台类似迪士尼 BD-X 的机器人**——性格、动作、表演由我设计；先在电脑里仿真，以后要不要做真机另说。

这不是求职作品集的主线（虽然以后可能顺便有用），**核心是创作：做出一个「像角色一样」的机器人**。

## 和迪士尼 BD-X 的关系

| 相同 | 不同 |
|------|------|
| 表达型 biped 角色，不是工业机械臂 | 不复制迪士尼硬件外形和内部闭源系统 |
| 动画师思维：动作、情绪、层次混合 | 角色造型、性格、动作库全部原创 |
| 上层「想做什么」，下层「怎么在物理世界里做到」 | 第一年先在仿真里站稳、表演，不急着真机 |

## 为什么需要 Isaac（给未来的我看）

**Blender  alone 做不出「机器人」。**

- Blender：你设计角色、绑骨、做 idle / 害羞 / 好奇 / 蹦跳等表演。
- **Isaac Sim**：给这台身体**物理**——关节、重量、脚会不会滑、头转快了会不会倒。没有这一层，只有动画片，没有「机器人」。
- **Python + JSON 状态机**：类似 BD-X 论文里的「动画引擎」——把「现在它很开心」变成 head_yaw、bounce 等低维命令，驱动仿真里的身体。

一句话：**Blender 是演员；Isaac 是带物理的舞台和机械身体。** 你的目标没变，Isaac 不是岔路。

## 仿真阶段要交付的「那一台机器人」

在电脑里算「做出来了」的最低标准（可调，但建议写死以免 scope 爆炸）：

1. **一个原创角色**（外形、性格你定）
2. **至少 4–5 种可切换的情绪/状态**（如 idle、好奇、开心、害羞、被吓到）
3. **头颈 + 身体**在物理仿真里**稳定站着**，动作看起来有表演感而不是乱抖
4. **一条可复现的管线**：Blender 动作 → 参数/命令 → 仿真里播放
5. **一段 1–3 分钟录屏**，能给别人看「这就是我那台机器人」

行走、跳跃、真机、RL 强化学习——都是**后面的加分项**，不是「没学会 Isaac Lab 就不算做过」。

## 技术栈（只为仿真里的 BD-X 服务）

| 用途 | 工具 |
|------|------|
| 设计、绑定、动画 | Blender 4.5 LTS+ |
| 资产传递 | OpenUSD |
| 物理机器人仿真 | Isaac Sim 5.1 |
| 情绪/动作切换与命令 | Python + JSON |
| 可选：更聪明的控制 | Isaac Lab（以后再说） |

第一年锁定 **Isaac Sim 5.1**，不追 6.0 / Newton，减少折腾。

## 三档范围（按「做出来」而不是「求职」）

| 档位 | 含义 |
|------|------|
| **做完** | 上面「仿真阶段最低标准」全部达成 |
| **做得好** | 更多情绪、动作混合更顺、镜头和录屏更像作品 |
| **以后再说** | 行走、真机、Jetson、ROS 2 |



## 有 AI 时的学习方式

- **不追求**系统上完 Python / Robotics 网课；**追求**每个阶段产出能跑、能录屏。
- **AI 写代码**，你负责：定需求、运行、验收、懂 enough 原理能改方向。
- 详见 [how-to-learn-with-ai.md](./how-to-learn-with-ai.md)

## 每周节奏（参考）

约 **20–24 小时/周**；每 **2 周** 至少有一次能录屏的进展（哪怕只有头在动）。

## 不做的事（防止项目死掉）

- 不追求复刻迪士尼每一颗螺丝
- 第一年不硬啃「从零训练双足走路」
- 不为买硬件而买硬件（Jetson 等真机前置）
